# 과제 1 - 하드코딩 키 리팩터링 실습

## 무엇이 위험했는가
- API 키와 DB 접속 문자열에 포함된 비밀번호가 소스 코드에 하드코딩되어 있었다.
- 소스 코드가 git에 커밋되거나 공유되면 키와 비밀번호가 함께 노출될 수 있었다.
- DB 접속 문자열 전체와 API 요청 헤더를 디버그 로그로 출력하여 실행 로그에도 비밀 값이 남을 수 있었다.

## 어떻게 고쳤는가
- API 키와 DB 접속 문자열을 '.env' 파일의 'API_KEY', 'DB_URL'로 분리했다.
- 'python-dotenv'의 'load_dotenv()'로 실행 시 환경변수를 읽도록 수정했다.
- '.gitignore'에 '.env'를 등록하여 git에 올라가지 않도록 했다.
- '.env.example'에는 실제 비밀 값 대신 설정 형식과 예시만 작성했다.
- 환경변수가 설정되지 않으면 실행을 중단하도록 검증을 추가했다.
- API 키와 DB 비밀번호가 출력되지 않도록 민감한 디버그 로그를 제거했다.

## 실키가 노출되었다면 올바른 대응 절차
1차 커밋에서 실키가 노출되었다면 이미 올라간 키는 즉시 폐기/재발급한다.
